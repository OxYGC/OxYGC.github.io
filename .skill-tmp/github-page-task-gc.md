# 资讯雷达（github-page-task-gc）

## Overview

雷达＝**取数 + 本地存档 + GitHub Pages** 三段，缺任何一段都算这次没跑完（用户 2026-10-16 定口径）。它把散落在二十多个来源的优惠、限免、行业动态与币圈信息收成一天的产物，并在交付前完成核实与价值分级：

1. **取数**——`scripts/radar_fetch.py` 一轮 25 个来源，归一化成 NDJSON，跨天去重。
2. **本地存档**——`$INFO_HOME/daily/YYYY-MM-DD.md`，本地真源，六段结构见第五节。
3. **GitHub Pages**——`$PAGES_REPO/_posts/` 当天的雷达稿，风格 D，见 `references/publish.md`。

邮件不算这三段之一：它是雷达内容**随「早间日报」投递的那块版面**（第六节）。所以邮件通道挂了不影响雷达判为完成，报告里点名即可；反过来**只有邮件、没有 Pages，就是雷达没跑完**，不能交差。

**终点是报告，不是代办**——所有兑现动作由用户本人完成。

## 一、动手边界（红线，优先于本文件其余内容）

1. **只到报告**：不注册账号、不绑卡、不填支付/授权表单、不代领代下单、不点任何「立即购买/领取」按钮。给到用户的是官方页面直链 + 核实时间 + 需要的操作，由他本人去做。
2. **不教绕过规则**：不写批量注册、多号刷奖励、绕过风控/额度的玩法；不做「薅秃某站」的教程。免费额度类只报道官方公开政策。
3. **不带出凭据**：正文、md、邮件里一律不出现 cookie、token、webhook 地址、密钥值、内网地址、钥匙串内容。需要凭据才能兑现的条目只写「需要你自己登录」。
4. **数字必须核实**：价格、原价、额度、折扣、截止时间，一律以本次实际打开的官方页面为准，并记「核实于 YYYY-MM-DD HH:MM」。抓到的字段和官方页不一致时以官方页为准，并在条目里写明改过。
5. **不编造来源**：没实测通的源不进清单；抓不到就写「本轮未取到」，不用记忆、旧文或别的站的数据冒充。
6. **GitHub Pages 是雷达三段之一，不是待选项**（用户 2026-10-16 定口径）：取数、本地存档、Pages 同步每天都必须全部完成，Pages 不再每次单独要授权。但保留两道护栏：**publish.md 第六节的内容门槛不过就不 push**（缺核实时间、缺截止时间、未核实的混进「值得」），退稿并在报告里点名是哪一条卡住——这时本地存档照常保留；**当天已成功推过就不再重复 push**（一次运行只进一次 commit）。邮件不在三段里，它是日报的投递块，发不出去只算日报缺件。仍然禁止的是另一类对外动作：代注册、代下单、代领券不因这条授权而获得许可。
7. 站点入口若带 `token=`、`ticket=` 之类参数，只留干净 URL。iOS 的**兑换码型限免**反过来——`apps.apple.com/.../redeem?id=…&code=…` 里的 `code=` 是这条福利本身，不转载、不拼进产物，只留频道原帖链接让用户自己取。
8. **币圈再加一层**：不连钱包、不签名、不导私钥、不代充代提、不点任何「连接钱包 / 领取空投 / 交易 / 提现」，不给买卖建议与目标价（详见 `references/crypto.md` 第六、七节）。产物里不出现钱包地址、私钥、助记词与带 `?ref=` 的邀请返利链接。

## 四、五步链路

### 1 取数

```bash
cd "$SKILL_DIR"
python3 scripts/radar_fetch.py --all --days 2 \
  --seen "$INFO_HOME/state/history.jsonl" \
  --append "$INFO_HOME/state/history.jsonl" > /tmp/radar.jsonl
```

- 输出 NDJSON，一行一条 `{id, cat, source, title, url, price, until, ts, extra}`；末尾 `SUMMARY fetched/fresh/sources/errors`。
- 单来源失败只打 `ERR source=x ...`，不影响其余来源；**`errors` 不为 0 就必须在日报里点出是哪条源挂了**，不能当无事发生。
- 全量一轮（25 源）2026-10-16 实测约 **48 秒**、抓到 **318 条**，`--days 2` 过滤后 241 条新，0 个 ERR。比 10-15 那轮（23 源 / 31 秒 / 299 条）多出的约 17 秒全花在 `appstore` 的逐条 iTunes 核价上。`--days 2` 只留近两天的条目（ISO 与 RSS 的 RFC 822 时间都能判；trending/steam 无发布时间戳，不受约束）。
- 只跑某条赛道：`--source lowendbox,ithome`、`--source epic`，或直接给组名 `--source crypto`（币圈 11 源）/ `deal`（优惠限免 6 源，含 `appstore`/`appinn`；10-16 实测 25 秒、`fetched=56 fresh=40 errors=0`）/ `news`（开发 AI 资讯）。组名在脚本的 `GROUPS` 里展开，新增币圈源要同时加进 `GROUPS["crypto"]`。
- 首次跑（history 还不存在）会出现 `fresh==fetched`，属正常。
- Epic 的 `price` 是原价折算、`until` 是领取截止；trending 的 `extra` 里带描述截断与 star 数。
- **App Store 限免层（`appstore`）一轮最多核价 15 条**（`APPSTORE_VERIFY_MAX`），而且**最新的先核**——早先按帖子顺序花额度，结果额度被旧帖吃掉、当天的限免全标「未核价」。超出额度的条目明写「未走 iTunes 核价（超出本轮核价上限）」，不猜价。人工抽查单个 app 用 `python3 scripts/radar_fetch.py --lookup 6753570922`（给 id 读国区现价）或 `--lookup "Idle Isle"`（给名字只出候选，**国区常改名，认 id 不认名字**）。
- `ERR source=x empty` 才是改版；业务上本来就常没货的源（`appinn`）挂 `allow_empty`，打印 `INFO source=x empty=` 不进 errors。别把这个开关当静音用的。
- 币圈源的字段口径单独立档（Binance 的日期只写在标题里、行情快照的 `id` 必须带当天日期、异动过滤门槛、`coindesk` 要跟 308），改脚本前先读 `references/crypto.md` 第三节。App Store 层的取法/核法口径同样单独立档，见 `references/sources.md` 第二节末。

### 2 验真

分级之前必须做，不可跳过：

- 优惠/限免/额度类：打开官方页确认价格与截止，截图或抄下页面上的原文数字。**只来自资讯源转述、官方页没核实到的，降级为 👀观察 并写明「未核实」。**
- iOS 限免类（`appstore`）：汇总频道只管「今天有什么在限免」，**价格必须回 iTunes lookup 用播报正文里的 `trackId` 核**（认 id 不认名字——国区会改名，按名字会认错 app、把别人的免费价安到这条上）。核到 `price==0` 只写「下载不花钱」，**不写「限免仍在」**（接口分不出本就免费与促销中）；核到现价非 0（实测 KoiFiles 播报「本体限免」而国区卖 ¥8）就判「限免已失效或已改价」，这条就是不做核价会误报的形态；查不到 id 就写「价格未核实」。内购限免与兑换码型一律只算转述（内购价不体现在下载价上；兑换码不转载，只留原帖）。Apple 不公布促销截止时间 ⇒ **不写截止时间**，别为了版式齐就补一个。口径全档见 `references/sources.md` 第二节末。
- 资讯类：RSS/API 里带旧时间戳的不算今天的新闻；GitHub trending 的新库要读一眼 README 判断是否真在解决用户关心的事，不凭名字吹。
- 币圈类：公告要回到交易所公告原文核对**生效时间与合约地址**（链上资产必核合约地址，代币符号重名太多，只按符号认资产会认错）；行情类只报快照时间与来源，不加任何方向判断；安全事件只认项目方 advisory / 官方博客 / 交易所公告三方之一，媒体转述单独出现时降为 👀；空投钓鱼、治理论坛里的骗子回帖（如「帮你追回被盗币」）一律 ❌，不写进任何段落。口径见 `references/crypto.md` 第五节。
- 疑似重复：`history.jsonl` 只挡同一 id；换标题重推的旧活动靠人和 URL 再判一次，判定为旧闻就 ❌过滤。
- 403 / 需要登录态的源（Epic 网页版、LowEndTalk、keylol、知乎、Reddit、Steam 页面）只走**操作系统默认浏览器那条桥**（`user-browser-use`；`chrome-devtools` 已停用，AI/Agent 内置浏览器 `browser-use` 不带用户登录态、不得用来跑登录源），且**不要用 `get_network_request`**——它会倒出整站 cookie。浏览器桥不可用时如实写「本轮需登录态的源未取」。

### 4 存档与发布

雷达三段落在链路的这几步上：**取数＝第 1 步，本地存档与 GitHub Pages＝本步**。这三段齐了才算「今天雷达跑完」，本步之后的回写（第 5 步）是台账，邮件是投递块——它们都补不上缺的那一段。

- **本地存档**（三段之一，自动写）：`$INFO_HOME/daily/YYYY-MM-DD.md`，六段见第五节。
- **GitHub Pages**（三段之一，每天必做）：把当天内容整成 `$INFO_HOME/out/YYYY-MM-DD-info-radar.md` 的稿，再放进 `$PAGES_REPO/_posts/YYYY-MM-DD-info-radar.md`。**版式固定用风格 D**（首屏行动清单表 + 2 个 H2 + `<details>` 卡片、正文 0 个 H3，见 `references/publish.md` 第七节）。front matter、htmlproofer 与构建排除的五道坑、代理 push、图片本地化——全部按 `references/publish.md` 执行，不要凭印象。
  - **每篇必须显式写 `permalink: /posts/info-radar-YYYY-MM-DD/`**。站点 `_config.yml` 的 post permalink 是 `/posts/:title/`，不含日期；文件名去掉日期后的 slug 每天都一样，不覆盖 permalink 就会让今天这篇把昨天那篇顶掉（实测：10-15 那篇没写 permalink，占着 `/posts/info-radar/`）。这条 permalink 同时是首页/详情页「雷达」品牌配色的唯一判据（`publish.md` 第八节），配色在站点公共层按 permalink 自动命中，稿内不加任何样式字段。
  - push 前跑 publish.md 第六节的内容门槛自查；**门槛不过就退稿**，本地存档与邮件照常交付，并在报告里点名是哪一条卡住——这时雷达按「Pages 段未完成」如实报告，不能报成跑完。
  - 上线判据是**三件套**，不是「URL 轮询到 200」这一条：① 本次 `Build and Deploy` 的 `conclusion`；② 站点首页 `curl -sI` 的 `last-modified` 已推进到本次 commit 时刻；③ `sitemap.xml` 里有本篇的 `/posts/info-radar-YYYY-MM-DD/`。三条全过才算上线。10-17 就是①②都过、③缺失——工作流绿但产物里根本没这篇，根因是 front matter 的 `date`（06:52）晚于 push 时刻（06:43），Jekyll 默认 `future: false` 把它从构建里剔除了。所以 **`date` 只能写已经过去的时间**（用实际取数完成时刻，宁可写早几分钟），这是 publish.md 第三节坑 5。（站点侧 10-18 已加 `future: true`、commit `ce675ad`，这一类已封顶；但习惯照留——`date` 同时决定列表排序时点。）
- **邮件**（日报的投递块，不算雷达的段）：用 `tools/mail-notify/send_mail.sh`，主题前缀 `[☀早间日报 MM/DD]`，正文一律 `--body-file`、`--format html`，排版见第六节。

### 5 回写

- `history.jsonl` 已在取数时 `--append`，人工补进去的条目（浏览器桥拿的）也要写同一条 JSON，否则明天重复报道。
- 跑完必须在日报末尾记录 `SUMMARY` 与每条 ERR；来源连续 3 天挂同一个错，就在日报里建议改脚本或换源。

## 五、本地存档结构（六段固定顺序）

```markdown

## 结论
一句话：🔥 n 条需要立刻处理 / ⭐ m 条值得 / 👀 k 条观察；本轮取数 x 条，y 个来源异常。

## 🔥 需要立刻处理
（没有就整段删掉，不留空壳）
- **标题** — 价值一句话｜价格或额度｜**截止 10-15 20:00（剩 x 小时）**｜[官方页](url)｜核实于 10-15 06:32

## ⭐ 值得看
### 优惠价格
### 限免
### 免费额度 / 羊毛
### 开发 · AI 动态
### 币圈

## 👀 观察（存疑或门槛高）
- 一行一条，末尾必须写存疑原因

## 来源健康度
| 来源 | 本轮条数 | 状态 | 备注 |

## 发布落点
- 本地存档：`$INFO_HOME/daily/YYYY-MM-DD.md`
```

## 七、来源维护

来源清单、实测状态与「机器可读 / 需代理 / 需浏览器桥 / 需登录态 / 待验证」的三档分类在 `references/sources.md`。币圈单独一档：`references/crypto.md` 记四轴取法（交易所公告 / 行情榜单 / 项目方一手 / 媒体转述）、X 为什么没有机器可读通道与浏览器桥的关注清单、验真口径（合约地址、快照时间、安全事件只认一手）、分级门槛与边界。**App Store 限免同样单独立档**——它在 `sources.md` 第二节末有一整块「怎么取、怎么核」的实测口径（两层拼法、认 id 不认名字、`price` 能证明什么、无截止时间、核价额度、`ident` 带日期）。**新增或换源必须先实测再写表**：

1. `curl -sI`（必要时带 `-x http://127.0.0.1:7897`）拿状态码；境外站本机无直连出口，200 要注明走的是代理。
2. 能机器读的 JSON/RSS 才往 `radar_fetch.py` 的 `SOURCES` 里加；解析函数返回归一化 dict 列表，务必给 `cat` 选对赛道，币圈源还要同时加进 `GROUPS["crypto"]`、优惠限免源要加进 `GROUPS["deal"]`，否则 `--source crypto` / `--source deal` 漏跑它。**赛道没有官方接口时（iOS 限免就是）不要硬造一个**：做成「汇总通道做发现 + 官方接口逐条核价」两层，并且核不到的部分只能标未核实。
3. 403 或要登录的，只进 `sources.md` 的浏览器桥档，不进脚本。
4. 某源连续报 `ERR source=x empty`（抓到 200 但解析 0 条）＝改版，先手工打开对照再改正则，不要直接删源。**只有业务上本来就常没货的源才挂 `allow_empty`**（如 `appinn`），它打印 `INFO source=x empty=`、不进 errors；这个开关不是静音键，挂了就没有改版报警。

## 八、定时挂载（挂在已有的早间日报里）

- **没有新建 cron**：雷达是已有那条「早间日报（每天 06:30）」（`Asia/Shanghai`，jobId `8e4cb1d7-679f-4d30-baf4-b0b0ea6df9c2`）的**第 6 步**，替换掉它原来那块「早间新闻：没配源就明写占位」的空壳；邮件的「早间新闻」块同时换成「资讯雷达（⭐ 值得 / 👀 观察 / 来源健康度），值得段按五赛道分组、含币圈」。全天只此一封，不再单独挂一条 6:30。
- 该步跑的顺序：取数（`--all --days 2` + `--seen/--append` 去重，一轮覆盖五条赛道，2026-10-16 实测约 **48 秒 / 318 条 / 25 源**；比 23 源那轮的 31 秒多出的时间全在 `appstore` 逐条回 iTunes 核价上，06:30 那一轮的预算按 1 分钟算）→ 验真 → 分级 → 写 `$INFO_HOME/daily/YYYY-MM-DD.md`（本地存档）→ 出雷达稿并 push `$PAGES_REPO/_posts/`、用线上 URL 回读（Pages）→ 随当天日报邮件投递 → 回写 `SUMMARY` 与各 `ERR`。
- **cron 那一轮的三段判据**：取数、本地存档、Pages 齐了才算「今天雷达跑完」。Pages 段没做成（内容门槛退稿、构建失败、push 或回读不过）时，当天日报末尾与邮件里必须明写「Pages 未同步」加卡住的原因，不许只报雷达内容就交差。
- **不做静默失败**：`--all` 一条没取到 = 雷达故障，在邮件里红字点名（境外源整批挂而境内源全绿时先怀疑代理节点，不是站点改版）；取数全崩到无法出报告才走 `[⚡紧急]` 主题单独通告。
- 晚间 18:00 档按用户决定暂不挂（那条 18:00 任务是发文打卡，不含雷达）；要加时先 `qoder_cron list` 对上现有任务再 update，**不新建重复任务**。
- **改口径要同时改两处**：本 SKILL 与那条 cron 的 prompt（cron 执行时不继承对话、也不会自动读本文件）。改 prompt 用 `qoder_cron` 的 `update` + 完整新 prompt，中文写字面汉字，改完逐字对比返回的 `instruction.text`。
- **现状（2026-10-18）**：那条 cron 的 prompt 已经是 **v6**（`qoder_cron update` 只替 `prompt` 一个字段，`30 6 * * *` / `Asia/Shanghai` 没动；回读的 `instruction.text` 与 `/Volumes/GC64SD/blog/.notify/morning-prompt-live-v6.txt` 逐字节相同，revision 6）。以后再改口径，以这份文件为基线，改完整份覆盖、再逐字比对回显。**这次覆盖不是措辞翻新**：旧 prompt 第 6 步第 8 条的内容门槛明写「优惠/限免必须有截止时间」，而 Apple 不公布促销结束时间，照旧口径跑会把所有 iOS 限免挤出 ⭐ 值得、甚至整篇退稿——v6 里那句「唯一例外是 App Store 限免…缺这句才算卡门槛」才是让 iOS 那层能落地的东西。
- 挂进或改动 cron 是对本机调度系统的改动，动手前向用户确认一次时间口径。
